NEW-1: Discount After Unpaid Events

Detection Rule

Same as cancel_after_unpaid (CR-544 v2), but for discount operations instead of cancellations:

For each order with make_unpaid history:
  For each discount apply/remove/replace
    WHERE discount_time > first_make_unpaid_at:
      → Emit discount_apply_after_unpaid or discount_remove_after_unpaid

Rules (same as CR-544):
  - Re-payment does NOT close window
  - Use FIRST make_unpaid_at
  - No time limit
  - Replace = 2 events (remove old + apply new), operation="replace"

Three Discount Flows (same as CR-546)

#FlowEvents Emitted
1Apply (no prior discount → added)1× discount_apply_after_unpaid with operation: "apply"
2Remove (discount → none)1× discount_remove_after_unpaid with operation: "remove"
3Replace (A → B)2× events: remove (old) + apply (new), both operation: "replace"

Overlap with CR-546

A discount event can trigger BOTH discount_*_after_print (CR-546) AND discount_*_after_unpaid (this ask). Backend emits both independently. FE handles multi-category display (Approach C).

NEW-2: Re-pay Gap Event

Detection Rule

For each order where:
  1. make_unpaid history exists AND
  2. Order was subsequently re-paid AND
  3. gap_amount = original_amount − repaid_amount > 0

Compute breakdown:
  gap_from_cancellations = sum of cancelled item ₹ (between unpaid and re-pay)
  gap_from_discounts = net discount ₹ change (between unpaid and re-pay)

Invariant: gap_amount = gap_from_cancellations + gap_from_discounts
(no other reasons for gap — only cancellations and discounts change order total)

Validation Checklists

NEW-1: Discount After Unpaid

□ Detection uses FIRST make_unpaid_at
□ Re-payment does NOT close the window
□ No time limit on gap
□ All 3 discount flows: apply, remove, replace
□ Replace = 2 events, both operation="replace"
□ discount_type: "percent" or "fixed" only
□ discount_amount = actual ₹, discount_value = raw input
□ gap_minutes = floor((discount_time − made_unpaid_at) / 60)
□ order_status_at_discount reflects status at moment of change
□ KPI counts: replace increments BOTH
□ Overlap with CR-546 OK — emit both independently
□ Existing cancel_after_unpaid unchanged

NEW-2: Re-pay Gap

□ Only emitted when gap_amount > 0
□ original_amount = total at FIRST make_unpaid
□ repaid_amount = total at re-payment
□ gap_from_cancellations + gap_from_discounts = gap_amount
□ Only counts changes in window (after unpaid, before re-pay)
□ No event if never re-paid
□ No event if re-paid at same/higher amount
□ Multiple cycles: FIRST unpaid → LAST re-pay
□ repay_gap_count + repay_gap_total KPIs returned
